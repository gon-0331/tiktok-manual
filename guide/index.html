＆ 準備するもの

「マニュアルをアプリにしたい」みたいな相談を、
手戻りなく、短い時間で形にするための手引き。
対象　AIに作業を頼む人（専門知識は不要）
もとになった実例　TikTok Lite 招待マニュアルのツール化／スマホアプリ化（2026年10月）
作成日　2026年10月14日

CHAPTER 01いちばん大事なこと

うまくいくかどうかは、作る前に何を渡したかでほぼ決まります。きれいな指示文を考えるより、手元の材料をそのまま出すほうが先です。

覚えるのはこの3つだけ

① 散らかったまま渡す　整理してから渡そうとすると、いつまでも始まりません。
② ゴールだけ言う　作り方は任せる。どんな技術を使うかは決めなくていい。
③ 分からないことは「分からない」と言う　これが抜けると、それらしい嘘が混ざります。

実例 TikTok Liteのマニュアルは、Markdown 3本・教材HTML 8本・PDF 2本・セミナー台本 3本に同じ話がバラバラに書かれた状態でした。整理せずそのまま渡した結果、AI側が「カテゴリーの選択数が資料によって3〜4つと2つで食い違っている」「自演招待が、ある資料では推奨・別の資料では禁止候補になっている」という矛盾を見つけ出しました。先に自分で整理していたら、この矛盾は気づかないまま消えていました。

CHAPTER 02作りはじめる前に準備するもの

全部そろえる必要はありません。無いものは「無い」と言えば、後から足せる形で作ってもらえます。

  • 今ある資料ぜんぶWord・PDF・メモ・LINEの文面・手書き写真でも可。バラバラ・重複・古いものが混ざっていて構いません
  • 写真・スクリーンショット後からでOK。「写真は後で渡す。どれが要るか教えて」と言えば、必要な枚数と内容を先に出してもらえます
  • 確定していること／していないことの区別「ここは実機で確かめた」「ここは聞いた話」の線引き。これが一番大事な材料です
  • 誰が見るか自分だけ／社内メンバー／生徒さん。これで作りが大きく変わります
  • どこで使うかパソコンで読む／作業中にスマホで見る／印刷して配る
  • 見せたくない相手がいるかいるなら合言葉やパスワードが要る、と最初に言っておく
  • アカウント公開するならGitHubなど。作成とログインは本人しかできません（→ CHAPTER 07）
資料が古くても捨てない

「これは古いかも」という資料こそ渡してください。新旧を突き合わせて、どこが変わったのかを見つける材料になります。捨てるかどうかは、突き合わせた後で決めれば間に合います。

CHAPTER 03最初に言う3つのこと

長い説明はいりません。この3つが埋まっていれば、設計まで任せられます。

言うこと例（TikTokマニュアルの場合）
① 何に困っているかキャンペーンの金額が変わるたびに、教材を全部手で直すのが大変
② 誰が使うか自分と、招待メンバーへの配布
③ どこで使うか作業中にスマホで見たい
この3つから決まったこと ①から「事実を1か所に集めて、そこから全教材を自動で作り直す形」、②から「他人が読んで分かる書き方と、配れる形式」、③から「スマホアプリ化」。作り方を一言も指定していないのに、設計はここで決まっています。

CHAPTER 04指示の出し方・6つのコツ

1. 手段ではなく、ゴールを言う

「HTMLで作って」ではなく「スマホで見られるようにして」。手段を指定すると、もっと良い作り方があっても、そこで止まってしまいます。

2. ふわっとした基準で言っていい

他人が見た時にでも分かるぐらい、分かりやすい教材にして

これで十分伝わります。「専門用語を使わず、手順を番号で、写真つきで」と細かく言わなくても、この一言が全部を決めます。

3. 分からないことは、決めさせない

分からないことは勝手に決めないで、「要確認」として残して

これを言っておくと、あいまいな点をそれらしく埋められずに済みます。後から実機で確かめて埋めればよく、未確定のまま進めても事故になりません。

4. 「完成」の定義を先に決める

作っただけで終わるのか、公開まで含むのかを最初に言います。毎回「公開して」と言わずに済みます。

これからは、直したら公開して、ちゃんと見られるかの確認までやって

5. 一度に全部言わなくていい

後から足せる形に作ってもらえば、思いついた順に言えます。実際この教材も、作ってから「QRの章を消して」「準備の章を足して」「Gmailの作り方も足して」と後出しで育ちました。

6. ダメ出しは、具体的に

伝わりにくい伝わる
開けない開けない。合言葉を入れると「ちがいます」と赤字が出る。iPhoneのSafariから
なんか違う文字が小さくて、作業しながらだと読めない
使いにくい毎回トップに戻るのが面倒。前に見ていた所から開きたい
「何が起きたか」を1行足すだけで解決が早い

画面に出た文字・使った端末・どこから開いたか。この3つがあると、原因の切り分けがほぼ1回で終わります。実際「開けない」だけでは原因が5通りあり、確認のやり取りが増えました。

CHAPTER 06作ってもらうときに入れたい仕組み

この6つを最初に頼んでおくと、あとで自分が楽になります。技術的な中身は分からなくて構いません。言葉だけ覚えてください。

頼むことなぜ必要か
原本は1か所にして同じ事実が2か所にあると、必ず片方が古くなる
変わる数字は別にして金額・日数・条件を1行直すだけで、全部に反映される
未確定が一覧で出るようにして何が埋まっていないかが、毎回目に入る
スマホで見られるように現場で使えないマニュアルは読まれない
更新してもURLは同じに配った後にリンクが変わると配り直しになる
直し方のメモも残して間が空いても、どこを触ればいいか自分で分かる

できあがる作業の流れ

  1. 原本を直す直す場所は1か所だけ。文章か、数字のファイルか
  2. 作り直すコマンド1つ。配布物が全部まとめて新しくなる
  3. 画面で確認するスマホの幅で、崩れていないか見る
  4. 公開して、公開先でもう一度確認する手元で直っていても、公開先が古いままのことがある

CHAPTER 07本人しかできないこと

ここだけはAIが代われません。先に済ませておくと、作業が止まりません。

  • アカウントの作成とログインGitHub・Googleなど。パスワード入力はAI側が行えません
  • 支払い・課金の操作金額が発生するものは必ず本人が確認して実行
  • 公開してよいかの最終判断外に出す内容の責任は本人にあります
  • 実機でしか分からない事実の確認「カテゴリーは何個選ぶのが正解か」などは、実際に触った人しか知らない
実例 公開先を用意する段階で、GitHubにログインしていなかったため作業が一度止まりました。ログインを済ませてからは、リポジトリ作成・ファイル配置・公開設定・公開先の動作確認まで、こちらの操作なしで完了しています。止まるのは毎回「本人しかできない所」です。

CHAPTER 08今回、何を経由して作ったか

新しく買ったものも、新しくインストールしたアプリもひとつもありません。すでに入っているものと、無料のサービスだけで完成しています。

使ったもの何に使ったか費用
Claude（パソコンのアプリ）指示を出す相手。文章づくり・ファイルの作成・画面確認・公開作業まで、ほぼ全部ここ契約プラン内
ChatGPTアプリアイコンの絵を1枚つくる契約プラン内
Google ChromeGitHubの操作、画像の受け取り、この指示書のPDF書き出し無料
GitHub公開するファイルの置き場所（アカウント作成が必要）無料
GitHub Pages置いたファイルをURLとして公開する（httpsつき）無料
Mac に最初から入っている Python原本から配布物をまとめて作り直す仕組みを動かす無料・導入作業なし
スマホのSafari／Chrome公開したURLを開いて、ホーム画面に追加する無料

どこからどこへ流れているか

  1. パソコンの中で作る原本（文章と数字）を直し、配布物を自動で作り直す。ここまでは外に何も出ていない
  2. Chrome経由でGitHubに置くできあがった1ファイルを、ブラウザからアップロードする
  3. GitHub PagesがURLとして公開する1分ほどで反映。URLは毎回同じなので、配り直しが要らない
  4. スマホのブラウザで開いて、ホーム画面に追加するこれでアプリのように立ち上がる。合言葉は端末が覚える
「アプリにする」＝アプリストアに出すことではない

今回のアプリは、ブラウザで開いたページをホーム画面に追加しただけです。審査も、ストアへの登録も、年間の費用もかかりません。アイコンから全画面で立ち上がり、見た目も動きもアプリと同じです。
AndroidでもiPhoneでも同じURLが使えます。

ひとつだけ気をつける所

公開した直後は、スマホに古い表示が残っていることがあります。開けない・変わっていないと感じたら、一度リロードするか、URLの最後に ?2 のような文字を足して開き直してください。実際この一度だけ「開けない」が起きました。

なぜGitHubを使ったのか

最初はGitHubを使っていませんでした。途中で必要になって移したというのが正確なところです。

移した理由 最初はClaudeの機能でそのまま公開し、URLも出ました。ただしそのURLはclaude.aiにログインしている人しか開けません。自分だけなら使えますが、人に渡せない。そこで「Claude経由じゃない形にしたい」となり、置き場所を探すことになりました。

探すときの条件は、専門的なことではなく、この5つだけでした。

条件なぜ必要だったか
無料で、ずっと置けるマニュアルは何年も使う。毎月払うほどのものではない
URLが変わらない配ったあとに変わると、配り直しになる
https で開ける合言葉の仕組みとホーム画面への追加に必要（下の囲み）
ファイルを置くだけで公開できるサーバーの設定を覚えたくない
広告が入らない人に見せる教材に広告が出ると困る

この条件で候補を比べた結果です。

候補判断
GitHub Pages採用。無料・https付き・URL固定・ファイルを置くだけ・広告なし
Netlify / Cloudflare条件は満たすが、結局アカウント作成が要る点は同じ。選ぶ決め手がなかった
レンタルサーバー月額がかかる。この用途には大きすぎる
Googleドライブ今はホームページとしての公開ができない
パソコンの中のファイルスマホのホーム画面に入れられない。合言葉の仕組みも動かない

もう一つ大きかったのは、このパソコンに何も入れずに済んだことです。本来こういう作業には専用のソフトを入れることが多いのですが、今回はブラウザのアップロード画面だけで更新できました。入れるソフトが増えないのは、後々きれいです。

「ファイルをそのままスマホに入れる」ではダメだった理由

合言葉で中身を開く仕組みは、ブラウザに元から入っている暗号の機能を使っています。これは安全なページ（https）でしか動きません。パソコンから送ったファイルを直接開く形だと、この機能が働かず、中身を開けません。
ホーム画面に追加してアプリのように使う機能も、同じくhttpsが前提です。どこかに置いてURLにする必要があったのは、このためです。

デメリットと、その潰し方

GitHubで無料で公開する場合、置き場所そのものは誰でも見られる状態になります。そこで、置くファイルの中身（本文・ルール・写真ぜんぶ）をまるごと暗号化し、合言葉を入れたときだけ開くようにしました。検索に出ないような指定も入れています。
つまり「公開の場所に置くけれど、中身は読めない」という形です。弱点が分かっているなら、先に潰せば使えるという判断でした。

内訳 Pythonの中では、文章の組み立て（Jinja2・markdown-it-py）、写真の圧縮（Pillow）、中身の暗号化（cryptography）、QRコードの作成（qrcode）、PDFの確認（PyMuPDF）といった無料の部品を使っています。どれも事前の導入作業は不要でした。名前を覚える必要はありませんが、同じものを作り直すときの手がかりになります。

CHAPTER 09まるごとコピペできる依頼文

最初の一通はこれで足ります。色のついた　◯◯　の部分だけ、自分の言葉に置き換えてください。

COPY & PASTE

　◯◯　をツール化して、常にアップデートできるようにしたい。

今ある資料は　◯◯　に入っていて、バラバラのまま整理できていない。古い情報も混ざっていると思う。

使うのは　自分と◯◯　で、　作業中にスマホ　で見たい。他人が見ても分かるぐらい分かりやすくしてほしい。

作るときは、原本を1か所にまとめて、そこから全部が自動で作り直される形にして。金額や日数みたいに変わる数字は、1か所直せば全部に反映されるようにしてほしい。

分からないことは勝手に決めないで「要確認」として残して、何が未確定か一覧で分かるようにして。

写真は後から渡すから、どんな写真が必要かを先に教えて。

進め方で迷ったら、勝手に決めずに選択肢を出して。

2通目以降は、思いついた順でいい

「◯◯の章を足して」「◯◯は消して」「合言葉を◯◯に変えて」。1行で足ります。最初に「公開と確認まで含めて」と言ってあれば、毎回お願いする必要はありません。

CHAPTER 10実際にかかった時間

参考までに、TikTok Liteマニュアルがどう育ったかの記録です。1日で完成させていません。使いながら足していった結果です。

日やったこと
1日目散らかった資料を渡す → 原本の集約、配布物の自動生成、矛盾3件の洗い出し
1日目「QRの章は消して」「準備と条件の章を足して」
2日目「端末で確認したいからアプリにして」「アイコンも作って」 → スマホアプリ化・公開
2日目「ログイン不要にして」「合言葉をかけて」 → 公開先を移して合言葉つきに
3日目合言葉の変更、表示の調整
6日目「Gmailの作り方も1つの章として足して」 → 章を追加して公開まで反映
最後に

完璧な指示を考えてから始める必要はありません。「◯◯をツール化したい、可能かな」で始めて、出てきたものを見てから直すほうが早いです。この手引きも、そのやり方で作られています。
